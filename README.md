# todorxoi — телеграм-бот «тодо бичиг»

Переводит калмыцкий текст между тремя формами записи и рисует настоящее
вертикальное письмо картинкой.

```
калмыцкая кириллица ──► транслитерация ──► тодо бичиг ──► картинка
       хальмг              xalimaq          ᡍᠠᠯᡅᡏᠠᡎ          🖼

фото или скан с тодо бичиг ──► транслитерация + тодо бичиг (юникод)
```

Тодо бичиг — ойрат-калмыцкое «ясное письмо», созданное Зая-Пандитой в
1648 году. Бот помогает читать и писать на нём тем, кто знает калмыцкий в
современной кириллице.

## Что умеет

**Три режима.** `/translit` — кириллица в транслитерацию на латинице.
`/todo` — запись тодо бичиг текстом. `/image` — картинка с вертикальным
письмом: строки сверху вниз, столбцы слева направо. Что именно вы
прислали — кириллицу, латиницу или уже тодо бичиг — бот определяет сам.
За раз принимается до 10 000 символов; если столбцы не влезают в одну
картинку, она приходит несколькими — по порядку, с номером в подписи.

**Настройка картинки** (`/settings`) — цвет надписи, фон, размер и шрифт.
Фон можно сделать прозрачным, чтобы накладывать надпись на свои
изображения; такая картинка приходит файлом, а не фото.

**Шесть шрифтов.** Классический работает с юникодом тодо бичиг.
Остальные пять — Clear Script, Biyir, Demberil, Garcaq, Zakaa — рисуют по
особой кириллической записи, которую строят статистические правила из
`assets/`; правила у них общие, отличается только начертание. Знаки
препинания ставятся в любом: запятая ᠂ и точка ᠃ — всегда, а бирга ᠀ в
начале и четыре точки ᠅ в конце — только если текст длиннее 100 символов:
короткую надпись незачем открывать и закрывать. В присланных шрифтах
знаков не было вовсе — дорисованы отдельными глифами, см.
`tools/add_marks_to_fonts.py`. Готовая запись ещё подгоняется под
начертание: у части пар буква заливает петлю соседней, и между ними
ставится «_» — короткий отрезок стержня (`tools/fit_spine_gaps.py`).
Подробности про саму запись — в `core/clear_script.py`.

**Фото → текст.** Фото или скан с тодо бичиг можно прислать в любом
режиме (или с командой `/ocr`). В ответ — транслитерация и юникод тодо
бичиг, по строке на столбец, и картинка с пронумерованными рамками
столбцов: видно, как бот разрезал страницу. Целая книжная страница
читается за пару секунд; наклон до 5° выпрямляется, колонтитулы и номера
страниц отбрасываются. Цвет не важен — жёлтое на оранжевом, белое на
чёрном, прозрачный фон: что текст, а что фон, решается по форме штрихов,
а не по яркости. Тёмный стол вокруг сфотографированной страницы тоже не
мешает. Если модель не уверена (на фото не тодо бичиг или
текст нечитаем), ответ помечается предупреждением.

**Исправление калмыцкого текста.** Многие набирают калмыцкий без
ә ө ү һ җ ң: «бяядл» вместо «бәәдл», «кюн» вместо «күн», «hалун» с
латинской h вместо «һалун». Модель на таком вводе ошибается в трёх словах
из четырёх. Режим `/fix` возвращает калмыцкие буквы и показывает, что
поменял, а кнопки под ответом сразу переводят исправленный текст дальше.
В остальных режимах исправление включается в `/settings` (по умолчанию
выключено): тогда бот правит текст сам перед переводом. Если
исправление выключено, а текст на такой похож, бот подскажет про
настройку. Правильно набранный текст не меняется. Слова, которые пишутся
по-разному и без спецбукв (цаган и цаһан, дакад и дәкәд), тоже не
меняются: по одним буквам их не различить.

**Исправления.** Под каждым ответом 👍 и 👎. По 👎 бот просит правильный
вариант и сохраняет пару «что выдал бот / как надо» — по этим
исправлениям модель потом дообучают. Это главная причина, по которой бот
вообще существует: размеченных данных для калмыцкого мало.

| Команда | Что делает |
|---|---|
| `/translit`, `/todo`, `/image` | переключить режим; можно сразу с текстом: `/todo хальмг улс` |
| `/fix` | исправить калмыцкий текст: вернуть ә ө ү һ җ ң |
| `/ocr` | фото → текст; можно подписью к фото или ответом на фото, а можно просто прислать фото |
| `/settings` | цвет текста, фон (в т.ч. прозрачный), размер шрифта; исправление текста без калмыцких букв |
| `/mode` | какой режим включён |
| `/cancel` | отменить ввод исправления |
| `/stats`, `/export` | статистика и выгрузка исправлений (только админам) |

## Как это работает

Транслитерацию делает связка из двух частей: слово сначала ищется в
словаре проверенных пар (27 034 слова), а чего там нет — предсказывает
небольшая seq2seq-модель посимвольно. Дальше транслитерация переводится в
юникод тодо бичиг по таблицам соответствия букв.

Модель считается на NumPy (`core/model_numpy.py`) — 1.5 млн параметров,
слово переводится меньше чем за миллисекунду. Torch не нужен ни для чего:
он тянул за собой пять гигабайт CUDA-библиотек ради сети, веса которой в
float16 занимают 3 МБ.

Картинку рисует `core/shaper.py`: HarfBuzz подбирает формы букв
(монгольское письмо курсивное — у буквы разный вид в начале, середине и
конце слова), FreeType растеризует глифы.

```
bot/     телеграм-слой на aiogram 3
core/    транслитерация, тодо бичиг, рендер — от телеграма не зависит
model/   веса моделей: транслитерация (NumPy), распознавание фото (ONNX int8),
         словарь для текста без калмыцких букв
assets/  шрифты и правила записи для семейства Clear Script
tools/   разовые скрипты: экспорт весов, сверка, подгонка шрифтов
```

`core/` можно дёргать отдельно, без бота:

```python
import core
r = core.process("Хальмг улс", "todo")
print(r.translit, r.todo)
```

Решения, которые выглядят неочевидно (почему дефис обрабатывается
по-разному, почему строка рисуется горизонтально и поворачивается, почему
рендер не использует рисование текста из Pillow), объяснены комментариями
в самих файлах.

### Текст без калмыцких букв

`core/fix_letters.py`, словарь `model/letters_vocab.tsv.gz` (103 тыс. слов
с частотами, 420 КБ, в памяти ~35 МБ):

1. Буквы-двойники внутри кириллического слова (латинская h, ə, ӧ, ҥ с
   чужих раскладок) заменяются калмыцкими.
2. Русский текст отсекается по служебным словам и словам на гласную.
3. Текст проверяется целиком: «ё», «яя», «э» в середине слова, согласная
   + я/ю в незнакомом слове, незнакомые слова, которые словарь
   восстанавливает, длинный текст без единой спецбуквы. Если ничего не
   сработало, текст не трогается.
4. В помеченном тексте незнакомые слова заменяются самым правдоподобным
   кандидатом из словаря: частота плюс цена замен (ә → я обычное дело,
   җ → дж редкость) с поправкой на то, как пишет автор в этом же тексте.
   Слова из словаря не меняются никогда.
5. Если целого слова в словаре нет, оно делится на основу и окончание:
   основа из словаря, окончание из собранных по словарю, гласные окончания
   согласованы с рядом основы (дугарна → дуһар + на). В режиме `/fix`
   незнакомые слова правятся, даже если текст в целом набран правильно;
   имена (слово с заглавной не в начале предложения) там не трогаются.

На отложенных книгах корпуса ловится 95–98% текстов без спецбукв, слов
восстанавливается 89–95%. В правильных текстах ни одно словарное слово не
меняется. Словарь пересобирает `python -m tools.build_letters_vocab`,
замеры и примеры лежат в `research/no_special_letters/`.

### Распознавание фото

`core/ocr.py`, модель `model/todo_ocr_int8.onnx` (CRNN + CTC, 4 МБ):

1. `core/page_layout.py` режет страницу на столбцы. Сначала картинка
   переводится в серое так, чтобы текст был тёмным при любых цветах
   (`to_gray`). Столбцы находятся по стержням букв — пикам вертикальной
   проекции чернил, граница — минимум между пиками; короткий последний
   столбец из одного слова тоже отделяется. Буквы раздаются столбцам целиком, поэтому хвосты,
   заехавшие под соседний столбец, не режутся. Наклон выпрямляется,
   колонтитулы, номера страниц и пыль скана выкидываются.
2. Каждый столбец поворачивается, приводится к высоте 64 и читается сетью.
3. Транслитерация — тем же `todo_to_translit`, что в текстовых режимах.
4. Рамки столбцов рисуются на выпрямленной странице и уходят картинкой.

Модель обучена на синтетике (14 шрифтов тодо бичиг) и переведена в int8
для onnxruntime: на одном ядре ~1 с на полную страницу. Модель и
библиотеки держат ~95 МБ постоянно, страница — ещё ~160 МБ на время
чтения. Распознавание идёт в отдельном потоке и по одной картинке за раз,
чтобы две страницы не удвоили память. Переобученную модель в формат бота
переводит `python -m tools.export_ocr_onnx` (см. описание в файле).

Скрипты в `tools/` нужны не боту, а разработчику: экспорт весов из
обученного .pt в .npz и сверка NumPy-реализации с torch слово в слово —
её стоит прогнать, если модель переобучат.

## Запуск

```bash
git clone https://github.com/vbadmaev1/todorxoi-bot.git
cd todorxoi-bot

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env     # впишите BOT_TOKEN от @BotFather
python -m bot.main
```

Проверить, что всё на месте, без токена и без сети:

```bash
python -m tests.smoke
```

### Деплой

Бот работает через long polling — ни домена, ни сертификата не нужно.
Экземпляр должен быть ровно один: два процесса с одним токеном будут
отбирать апдейты друг у друга.

С Docker: `docker compose up -d --build`. Без Docker — в
`deploy/todorxoi.service` лежит systemd-юнит с инструкцией.

Зависимостей мало: образ около 330 МБ, из них примерно 180 МБ —
onnxruntime и scipy для распознавания фото. Память (замер на macOS):
~300 МБ в покое с обеими моделями, пик ~460 МБ, пока читается полная
книжная страница. Тариф с 1 ГБ — с запасом, 512 МБ — впритык.

**Папку `data/` нужно вынести в volume** — в ней база с исправлениями. На
хостинге с эфемерным диском без этого весь собранный фидбэк исчезнет при
первом же рестарте. В `docker-compose.yml` это уже сделано.

### Переменные окружения

Все — в `.env.example` с комментариями. Обязательная одна: `BOT_TOKEN`.
Стоит сразу заполнить `ADMIN_IDS` (свой id подскажет `@userinfobot`),
иначе `/stats` и `/export` не будут работать ни у кого — так выгрузку не
скачает случайный человек.

## Данные

Бот сохраняет присланные тексты, результаты перевода и оценки — иначе
исправления не собрать. Если текст похож на набранный без калмыцких букв,
в `requests.letters_json` пишется, что сработало и что исправлено: по этим
записям настраиваются пороги `core/fix_letters.py`. Хранится это в SQLite рядом с ботом, наружу
никуда не уходит. Выгрузка `/export corrections` даёт CSV только со
строками, где человек прислал правильный вариант.

Параллельно всё пишется в `data/events.jsonl` — обычный текстовый файл,
по строке на событие. Он нужен на случай, когда файл базы теряется:
переезд, пересоздание контейнера, очистка диска. JSONL можно скопировать
откуда угодно, хоть из веб-терминала хостинга (`cat data/events.jsonl`),
и собрать базу заново:

```bash
python -m tools.restore_from_jsonl events.jsonl --db data/todorxoi.sqlite3
```

Повторный прогон ничего не задваивает, так что логи за разные периоды
можно скармливать скрипту по очереди.
